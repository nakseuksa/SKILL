# Java 17+（含 Spring Boot）OOD 惯用法与边界指南

> **适用范围**：单进程（单体/模块化单体）Java 17+ 应用。标记 `[§x.y]` 为原文原则，`[扩展]` 为 Java / Spring 生态适配。

以下内联片段为**设计草图**，可能省略文件拆分、依赖或项目类型。标注为可执行的例子单独链接到源码。

## 1. 语言特性基线（严禁混淆 Java 17 与 Java 21）`[扩展]`

| 特性 | 引入版本 | Java 17 可用性 | OOD 典型用途 |
|---|---|---|---|
| `switch` 表达式（箭头语法、枚举穷尽） | Java 14 | ✅ 可用 | 枚举（`enum`）分支无 `default` 编译期穷尽检查 |
| `record`（不可变数据载体、紧凑构造器） | Java 16 | ✅ 可用 | 具体类型（值对象、命令、事件、封闭变体分支） |
| `instanceof` 类型模式匹配（`x instanceof Foo f`） | Java 16 | ✅ 可用 | P17 受限运行时能力查询与 `equals` 实现 |
| `sealed classes / interfaces`（`permits`） | Java 17 | ✅ 可用 | P21 封闭变体集定义 |
| **`switch` 类型模式匹配与 `sealed` 穷尽检查** | **Java 21** | ❌ **Java 17 不可用** | **Java 17 下请改用 `sealed` 接口上的多态方法或 Visitor 模式**；升至 21+ 方可用 `switch (s) { case Card c -> ... }` |
| `record` 解构模式（`case Point(int x, int y)`） | **Java 21** | ❌ **Java 17 不可用** | Java 17 下通过访问器 `p.x()` 读取 |

## 2. 原语落地速查（P01–P21 Java 17 代码范式）

### P01–P05 · 包私有边界、局部嵌套类与三层契约 `[§24.4 · 扩展]`
```java
package com.acme.ordering; // 公开包界面：仅导出 Order 与 OrderingUseCase
public final class Order {
    private record LineItem(String sku, int qty) {} // P02: 从属概念局部化为 private static record
    private final java.util.List<LineItem> items = new java.util.ArrayList<>();
    void applyInternalAudit(OrderRepository repo) { repo.recordAudit(this); } // P04: 包私有协作 (近似 friend)
}
interface OrderRepository { void recordAudit(Order o); } // P01/P03: 包私有内部支撑契约
```

### P06–P08 & P20 · 不可变具体类型、紧凑构造器不变式与同包辅助类 `[§23.4.3.2, §24.3.7.1 · 扩展]`
```java
public record Money(long cents, String currency) {
    public Money { // P20: 紧凑构造器强保类不变式（替代默认关闭的 assert 关键字）
        java.util.Objects.requireNonNull(currency, "currency");
        if (cents < 0 || currency.isBlank()) throw new IllegalArgumentException("Invalid Money");
    }
    public Money add(Money other) { // P06/P07: 核心操作维护不变式并返回新实例
        if (!this.currency.equals(other.currency)) throw new IllegalArgumentException("Currency mismatch");
        return new Money(Math.addExact(this.cents, other.cents), this.currency);
    }
}
public final class Moneys { // P07: 非核心便利函数剥离到同包静态工具类
    private Moneys() {}
    public static Money sum(Iterable<Money> list, String cur) {
        Money total = new Money(0, cur);
        for (Money m : list) total = total.add(m);
        return total;
    }
}
```

### P09–P12 · 屏蔽子类型的组合委托与所有权对 `[§24.3.3, §24.3.4 · 扩展]`
```java
public final class ControlledField { // P10: 严禁 extends Field 暴露隐式转型，改用私有组合转发
    private final java.util.List<String> backing = new java.util.ArrayList<>(); // P11: 独占内聚包容
    private final AccessPolicy policy; // P12: 外部构造注入的多态策略引用
    public ControlledField(AccessPolicy policy) { this.policy = java.util.Objects.requireNonNull(policy); }
    public void append(String val) { policy.checkWrite(); backing.add(val); }
    public java.util.List<String> snapshot() { return java.util.List.copyOf(backing); } // P06: 防御性只读视图
}
interface AccessPolicy { void checkWrite(); }
```

### P13 · 显式消解接口同名 `default` 方法冲突 `[§25.6 · 扩展]`
```java
interface Window { default String draw() { return "render-window"; } }
interface Cowboy { default String draw() { return "pull-holster"; } }
// 用不同的角色视图暴露两个契约，而不是在同一 draw() 中同时执行两种业务。
final class CowboyWindow {
    Window asWindow() { return new Window() {}; }
    Cowboy asCowboy() { return new Cowboy() {}; }
}
```

### P14 · 非虚公开骨架与受保护扩展钩子（NVI）`[§24.3.2.1 · 扩展]`
```java
public abstract class Buffer<T> {
    public final void put(T item) { // Java private 方法不可被覆盖，用 public final 锁死主流程
        java.util.Objects.requireNonNull(item);
        if (isFull()) onOverflow(item); else doStore(item);
    }
    protected abstract boolean isFull();
    protected abstract void doStore(T item);
    protected abstract void onOverflow(T item); // P04/P14: 派生扩展契约
}
```

### P19 · 句柄与底层集合的并发契约 `[§25.7.1 · 扩展]`
**可执行 Java 17 示例**：[LockedSetHandle.java](../examples/code/LockedSetHandle.java)。句柄独占普通 `HashSet`，所有访问均经过同一把锁，不返回集合引用。只给写操作加锁却允许无锁读不满足这个契约。若选择并发容器或不可变快照，另行说明所保证的操作与一致性；单次调用安全也不等于多个调用组成原子事务。

### P21 · Java 17 封闭变体集（`sealed` + `record` + 多态方法）`[§24.3.4.1 · 扩展]`
```java
public sealed interface PaymentMethod permits PaymentMethod.Card, PaymentMethod.Wallet {
    Money feeFor(Money amount); // Java 17 下用接口多态方法替代 Java 21 的 switch 类型匹配
    record Card(String maskedPan) implements PaymentMethod {
        public Money feeFor(Money amount) { return new Money(amount.cents() * 2 / 100, amount.currency()); }
    }
    record Wallet(String walletId) implements PaymentMethod {
        public Money feeFor(Money amount) { return new Money(0, amount.currency()); }
    }
}
```

## 3. 组件边界工具（将 P01/P03 转化为自动化测试）`[扩展]`

### 3.1 按业务特性分包 + 包私有可见性
- 拒绝顶层按 `controller / service / repository / model` 水平切分（那会迫使所有类设为 `public`）。
- 按组件（如 `com.acme.ordering`、`com.acme.inventory`）分包：只有跨组件调用的接口、领域事件和命令 DTO 设为 `public`，内部实现类、Repository、辅助类一律**省略访问修饰符（package-private）**。

### 3.2 ArchUnit 架构不变式规则模板（A5 产出物）
```java
// 放置于 src/test/java/.../ArchitectureTest.java (需引入 com.tngtech.archunit)
@AnalyzeClasses(packages = "com.acme")
public class ArchitectureTest {
    @ArchTest // P03: 组件间依赖必须构成无环图 (DAG)
    static final ArchRule no_cycles = SlicesRuleDefinition.slices()
        .matching("com.acme.(*)..").should().beFreeOfCycles();

    @ArchTest // 框架引力防线：领域模型不依赖 Web/持久层具体框架
    static final ArchRule domain_stays_pure = ArchRuleDefinition.noClasses()
        .that().resideInAPackage("..domain..")
        .should().dependOnClassesThat().resideInAnyPackage("..web..", "org.springframework.web..");
}
```
> 若项目使用 **Spring Boot 3.x**，也可推荐使用 **Spring Modulith** 的 `ApplicationModules.of(App.class).verify()` 自动校验模块无环与包封装。

## 4. 框架引力检查清单（R0 逆向与 A4 审查必查）`[扩展]`

| 检查项 | 腐化信号（坏味道） | 按规模档位的修正策略 |
|---|---|---|
| **1. JPA 实体与领域模型混同** | 实体类满是公共 `setter`、无参构造暴露给业务层、为迎合外键放弃领域不变式 `[§24.3.7.1]` | **轻量档**：允许共用，但将无参构造设为 `protected`、删掉裸 `setter` 改用业务方法；**标准/严格档**：分离纯领域类与包私有 `*JpaEntity`（P10/P16） |
| **2. 领域层污染框架注解** | 核心领域值对象或实体直接依赖 `@RequestParam`、Jackson HTTP 细节或底层事务实现 | 领域类保持 POJO / `record`；序列化与路由注解留在边界 Adapter / DTO 层（P01/P08） |
| **3. 字段注入掩盖依赖膨胀** | 类内出现 10 个 `@Autowired private XxxService`，掩盖违反单一概念责任的胖类 `[§23.4.3.3]` | 一律改为**构造器注入**（或 `final` 字段 + 显式构造）；构造参数超过 5–6 个立即触发 L9 拆分检查 |
| **4. 外部 DTO 穿透进领域层** | 领域核心方法直接接收 `CreateOrderHttpRequest` 或返回外部三方 SDK 的响应类 | 违反 L8（同一抽象层次）与 P08（单向映射）；在入口处转换为领域命令或领域值对象 |
| **5. “上帝 Service” 过程式退化** | `OrderService` 长达 3000 行，而 `Order` 只有字段和 getter/setter `[§24.2.1]` | 违反“将概念表述为类 `[§23.7[11]]`”；把维护 `Order` 状态不变式的核心操作移回 `Order` 类内（P06/P07） |

## 5. A5 骨架代码生成约定 `[扩展]`

1. **目录结构**：`com.<org>.<component>` 根包下放置公开契约（`public` 接口、命令/事件 `record`、核心聚合根）；若组件较大，内部实现放入 `internal` 子包并配合 ArchUnit 禁止外部访问 `..internal..`。
2. **类默认封闭**：凡未明确设计为基类（角色 3 结点类）的具体类，一律加 `final` 或定义为 `record` `[§25.9[5]]`。
3. **不变式落地**：每个核心领域类必须包含构造函数参数校验或 `private void checkInvariant()`，对非法状态抛出明确的运行时领域异常 `[§24.3.7.1, §24.3.7.2]`。
