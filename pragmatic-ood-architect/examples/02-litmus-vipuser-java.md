# 局部重构：会员升级是否需要换对象？

**用户**：Java 17 的 `NormalUser` 存历史订单。我想让 `VipUser extends NormalUser` 来改折扣并加管家 ID，不要建蓝图。

**助手 · R0 → A3**：现有订单关联的是 `NormalUser`；`VipUser` 是你提议的新结构，还不是现状。决定继承之前，先查身份的生命周期（L2 `[§24.3.2]`）：同一账号会在保留订单历史的情况下升降级，还是开户后类型一直不变？

**用户**：可以随时升降级，ID 和订单历史都不变。

**助手**：那变化的是权益，不是账号。两种做法：

1. **`User` 持有可替换的 `MembershipTier`（推荐）**：折扣和专属管家归权益对象；降级不替换 `User`，已有订单引用仍然有效 `[§24.3.2 · 扩展]`。
2. **`User` 接受折扣策略，管家绑定单独维护**：若管家分配有自己的有效期、不跟等级一起变化，这样更合适。
