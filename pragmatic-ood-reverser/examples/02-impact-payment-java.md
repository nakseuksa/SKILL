# 变更评估：全额退款能否直接改为部分退款？

以 `examples/fixtures/java` 为目标根。这是 Java 17 领域代码的可读样本，不含 Spring 容器、数据库和网关实现。可复跑 `python3 scripts/scan_topology.py examples/fixtures/java`。

**用户**：只 review，不落盘。我要加部分退款，最先要验证什么？

**答复（`impact`，只读）**：先验证金额与重复调用，不要只给网关调用加个金额参数。

- **已观察**：`payment/RefundService.java:L10-L13` 拒绝已退款订单，向网关传入订单的**全部**已付金额，成功返回后才标记退款。`order/Order.java:L14-L15` 公开的是布尔标记，不记录累计退款额。这里读到的是这一条具体路径，不是部署中的交易记录。
- **推断** `[§24.3.7.1 · 扩展]`：若部分退款继续复用这个标记，第二次合法退款可能被拒；若删除守卫，又没有在此路径上看到累计上限。代码的善意解释是只服务“一次全退”，而不是原作者忘写了部分退款。
- **待验证**：网关异常或成功后本地标记未持久化时能否重试？`payment/RefundService.java:L6` 只是接口，无法从它证明幂等、事务边界或数据库唯一索引。先找实现、迁移与失败路径测试。
- **回归建议（未运行）**：同一订单两次部分退款累计不超实付；重复请求不重复退款；网关失败时保留可重试状态。累计上限是拟新增的业务契约，不冒充已存在的不变式。

不写地图，也不实施退款功能。若之后仅说“保存这份评估”而未给路径，只确认一次保存位置；收到答复再写。
